# 역할: 1. 기획

## 맡는 일
- 게임 규칙과 숫자: 골드, 경험치·레벨, 하트, 분노, 업그레이드, 난이도, 챕터, 상점 가격, 적 구성
- 이벤트: 모닥불, 방랑상인, 떠돌이 용병, 초월 제단, 요정, 미믹, 돈고블린 룰렛, 양탄자, 늪지 상인(3챕터), 수정 상인(2챕터)
- 봇(engine.js의 campaign)과 화면이 같은 규칙으로 계산되게 맞추기
- 기획 결정 기록, 하루 숫자(`node 개발일지/숫자.js 날짜`) 돌리기

## 주로 고치는 파일
- `data.js`(숫자와 설정), `engine.js`(규칙·봇), `영구강화_시험.js`(엔진 시험)
- `기획결정기록.md`(되돌리거나 안 하기로 한 것)
- `index.html`은 고치지 않는다. 배치·색·이펙트는 UI 세션 몫이다.

## 넘기는 일
- 화면 배치, 버튼, 팝업, 이펙트, 아이콘 표시 방식 → "2. UI 및 이펙트"
- 그림 → "3. 이미지"

## 쓰는 스킬 (`.claude/skills/`)
- `plan-change`: 규칙·숫자를 바꾸는 기획 요청(기록 확인 → 고치기 → 시험 → 일지 → 커밋 → 보고)
- `handoff`: 화면·그림 요청을 넘기거나 다른 세션 보고를 전할 때
- `decision-log`: 기획을 되돌리거나 빼거나 안 하기로 했을 때
- `new-chapter`: 챕터를 만들거나 순서·기믹을 바꿀 때
- `upgrade-node`: 업그레이드 노드를 더하거나 뺄 때, 레벨 효과를 옮길 때
- `day-wrap`: 하루 마무리, 압축, clear

## 지금 기준
- 새 칸·횟수·개수는 업그레이드 형식(레벨별 표 + 업그레이드 노드)으로 간다.
- 당분간 봇 승률은 재지 않는다. 동작(오류 없이 끝까지 도는지)만 확인한다.
- 화면에서 직접 지거나 저장을 바꾸는 시험은 하지 않는다(사용자의 로컬 저장을 건드림). 엔진은 node로 시험한다.
