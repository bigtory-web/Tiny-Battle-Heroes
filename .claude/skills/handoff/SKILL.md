# 다른 세션에 넘기기·보고 전하기

기획 세션은 화면과 그림을 고치지 않는다. 찾은 것과 함께 맞는 세션에 넘긴다(사용자: "각 세션한테 맡겨 다른 파트 일은").

## 어디로

| 일 | 세션 |
|---|---|
| 화면 배치, 버튼, 팝업, 이펙트, 아이콘 표시, `index.html` | "2. UI 및 이펙트" |
| 그림(영웅, 배경, 아이콘, 상인, 분노 아이콘) | "3. 이미지" |
| 화면에 새 그림을 붙이는 일 | 이미지가 만들고 UI가 붙인다 |

주소는 `ListAgents`의 이름으로 `SendMessage`.

## 넘길 때 형식

```
[기획] 한 줄 요약
사용자: "원문 그대로"
- 무엇을, 어디에(화면 이름·자리, 스크린숏이면 무엇이 보였는지)
- 엔진·데이터에서 쓸 것: 함수 이름과 돌려주는 값, 예시 값
- 아직 정하지 않은 것 / 사용자에게 보여 주고 고르게 할 것
```

- 모양·색·시간은 기획이 정하지 않는다. "UI가 정해서 사용자에게 보여 주세요"라고 넘긴다. 사용자가 말한 값만 넘긴다.
- 그림은 "1장 먼저 → 사용자 OK → 나머지"를 적는다. 픽셀랩은 비용을 먼저 말하게 한다.
- 엔진을 바꿔 화면이 잠깐 깨지는 경우(필드 이름이 바뀜 등)는 바뀐 이름과 `index.html` 줄 번호를 같이 적는다.

## 보고를 사용자에게 전할 때

- 다른 세션 보고는 사실 그대로 짧게 전한다. 한 것, 그 세션이 확인 못 한 것(눈으로 못 봄 등)을 같이 적는다.
- 배포 얘기("배포 대기", "다음 묶음")는 꺼내지 않는다.
- 보고에 기획이 판단할 것(데이터 값이 그림과 다름 등)이 있으면 고치거나 사용자에게 묻는다.
- 그 전에 물어 놓고 답을 못 받은 질문이 있으면 끝에 다시 묻는다.
- 그림 파일이 생기기 전에는 데이터에 그 파일 이름을 넣지 않는다(화면이 깨짐). 파일이 생겼는지 `ls`로 보고 넣는다.
