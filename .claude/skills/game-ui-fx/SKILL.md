# 유물·스킬 이펙트 만들기

"2. UI 및 이펙트"의 절차다. 저장 백업·화면 확인 방법은 `game-ui-screen-work`, 끝나면 `task-wrapup`. 그림 파일(`img/fx`)을 새로 그리는 일은 이미지 세션 몫이다.

## 1. 모양 (첫 안부터)

- 게임 도트 그림체로 만든다. 매끈한 원·고리, 얇은 선, 부드러운 번짐은 쓰지 않는다(`화면규칙.md` "유물·스킬 이펙트는"). 본보기: `index.html`의 `UXF.meteor`.
- "작다·약하다·별로"라는 요청은 크기보다 그림체를 먼저 본다.
- 터지거나 퍼질 때는 덩어리(불·연기·먼지·조각)가 변하며 흩어진다. 크기는 영웅보다 확실히 크게.
- 효과의 느낌에 맞춘다(바람은 날리게, 돌진은 돌진답게, 회복·화염·상태이상은 그 느낌).
- 여러 번 때리는 스킬은 한꺼번에 말고 하나씩 보여 준다(사용자: "박쥐 스킬 보면 3번 물어뜯잖아").
- 적 전체를 때리는 큰 이펙트는 맞는 적마다 겹치지 말고 하나로(유성).
- 너무 세면 줄여 달라고 한다(돌풍: "조금 과하다"). 화면 흔들림·전면 번쩍은 큰 것에만.

## 2. 코드 자리 (`index.html`)

- 유물: `UXF`(그리기), `relicFx`(터질 때), `relicHitFx`(맞는 적), `LINEFX`·`STKC`(배치·연계 유물), `uxAdd(종류, x, y, 옵션, 초)`.
- 도트 층: `PXK`에 이름이 있는 종류는 1/3 크기로 그린 뒤 도트로 굳힌다(`fxPixel`, `pxFlush`). 새 유물 이펙트 이름은 `PXK`에 더한다. 직접 칸에 찍어 그리는 것(유성)은 넣지 않는다.
- 궁극기: `ultImpact`, `ultCutIn`(`?ultfx=1` 시안). 공용 시트 이펙트: `fx.js`.
- 같은 이펙트를 여러 곳이 쓰는지 먼저 찾는다(예: `beat`는 궁극기도 씀). 말하지 않은 것까지 바뀌면 새 이름으로 만든다.

## 3. 확인

- 장면을 한 장에 늘어놓아 본다. `uxRgb` 앞에 임시로 `window.__rx = function(c2, n, o, k){ ... }`(ctx를 바꿔 `UXF[n]`을 부름)를 넣고, 시간 `k`를 0.2~0.9로 바꿔 영웅 그림 위에 그린다. 끝나면 지운다(`__rx`가 남지 않았는지 확인).
- 여러 대상에 동시에 뜨는 것은 한 장면 그리는 시간을 재 본다.
- 실제 전투를 한 번 돌려 콘솔 오류가 없는지 본다.
- 장면 그림을 사용자에게 보내고, 움직이는 모습을 못 봤으면 그렇게 적는다.

## 겪은 함정

- 새 함수 이름이 아래쪽의 기존 함수와 겹치면 뒤의 것이 덮는다(`pxDraw`). 만들기 전에 이름을 검색한다.
- 흔한 클래스 이름(`my`, `foe`, `field` 등)은 전장 CSS와 겹친다.
- `uxGlow`는 도트 층에서 아무것도 안 그린다. 빛이 주인 이펙트는 덩어리로 그린다.
- 옅은 전면 칠은 도트 층에서 바둑무늬 네모가 된다. 쓰지 않는다.
