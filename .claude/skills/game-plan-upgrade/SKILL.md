# 업그레이드 노드

화면 이름은 "업그레이드"(코드 안 이름은 meta). 새 칸·횟수·개수는 앞으로 이 형식으로 간다: 레벨별 표 + 업그레이드 노드.

## 더할 때

1. `data.player`에 레벨별 줄이 필요하면 만든다(숫자는 사용자가 말한 것, 없으면 "임시").
2. `data.meta.lines`의 맞는 갈래에 노드를 넣는다.
   - 값 더하기: `{ id, req: [앞 노드], name, unit: '칸'|'회'|'%'|'명', key 또는 path, add, cap?, cost: [...] }`
   - 등급 확률: `{ gradeUp: { table, grade: 2|3|4 }, add: 2, cost: [4, 8, 12, 16, 20], unit: '%' }` — 낮은 등급에서 빼고 높은 등급에 더함, 무게 합은 그대로
   - 노드 id가 영웅·몹 id(mimic, chest 등)와 겹치지 않게.
3. 설명은 "모닥불 리셋 횟수 +1 (기존 0)"처럼 레벨 1 값(`E.metaBase`)을 같이 보여 준다. 능력치 노드는 기존값 없이.
4. 시험(`영구강화_시험.js`): 다 찍은 상태 값, 원본 data가 안 바뀌는지, 다른 표로 새지 않는지.
5. UI에 트리 자리(UPPOS·아이콘)를 넘긴다. 루트가 다른 노드는 높이를 달리해 같은 줄처럼 안 보이게.

## 레벨 효과를 옮길 때

레벨로 오르는 것을 **엔진 전체에서** 찾아 빠짐없이 목록으로 보여 주고 사용자가 고른다(`game-plan-change`의 "레벨로 오르는 것을 말할 때"). 레벨업과 업그레이드가 둘 다 올리는지, 하나로 대체하는지 확인한다.

## 뺄 때

1. 노드를 `meta.lines`에서 지운다.
2. `data.meta.removed`에 `{ 노드 id: [단계별 비용] }`을 더한다. 화면이 열릴 때 `E.metaRefund`가 저장에 남은 단계만큼 훈장을 돌려준다(한 번만).
3. `game-plan-decision-log`에 남긴다.
4. UI에 트리 자리 정리를 넘긴다.
