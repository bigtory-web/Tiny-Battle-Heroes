# 플레이 테스트 (재미·버그)

직접 눌러 본 것만 보고한다. 코드를 읽기만 하는 검수는 `code-audit`. 코드·그림·숫자는 고치지 않는다.

## 시작 전

- `화면규칙.md`를 다시 확인한다(컴팩트 뒤에는 읽은 내용이 빠질 수 있다).
- 미리 보기 `testbed-qa`(preview_start 이름, http://localhost:8766)에서만 플레이한다. `localhost:8765`는 사용자의 저장 데이터라 열지 않는다.

## 기본 범위 (요청에 따로 없으면)

- 스테이지 1-1~1-10, 3판. 판마다 다른 길:
  1. 보통: 평소처럼
  2. 종 최대: 판마다 종을 3번
  3. 지기: 일부러 지고 다시 도전(위로금, 모닥불, 하트, 종 골드 중복 막기 확인)
- 같은 길을 여러 번 반복하지 않는다. 여러 판의 평균이 필요한 숫자는 플레이 말고 봇 시뮬레이션 몫이다(기획).
- 요청에 주제가 있으면(예: "상점만") 그 주제만 본다.

## 방식

- 코드를 넓게 읽는 조사는 서브에이전트에게 맡기고, 결론과 근거 파일 위치(파일:줄)만 받는다.
- 재미 의견은 "느낌"이 아니라 무엇을 했을 때 왜 그랬는지(예: "1-3에서 종을 안 울려도 3초 만에 이겨서 고를 게 없었다")로 쓴다.
- 승률은 재지 않는다(당분간 사용자 결정).
- 같은 버그를 두 번 이상 재현해 보고, 한 번만 일어났으면 그렇다고 적는다.
- 한 판이 끝날 때마다 찾은 것을 일지에 적고 다음 판으로 간다.

## 토큰 아끼기

- 화면은 글자로 읽는다(`read_page`, `get_page_text`). 캡처는 버그를 찾았을 때나 겹침·위치처럼 눈으로 봐야 할 때만, `scale` 0.5.
- 전투는 배속(X1.5)이나 스킵. 기다리는 동안 상태를 여러 번 확인하지 않는다.

## 보고 형식

항목마다:
- 중요도(높음·보통·낮음), 종류(버그·재미)
- 재현 순서: 어디서 무엇을 눌렀는지 1, 2, 3
- 기대한 것 / 실제로 일어난 것
- 스크린샷 경로(있으면), 콘솔 오류(있으면)
- 확인 못 한 것(휴대폰 화면 등)은 그렇다고 적는다.

넘길 때는 이 항목을 그대로 보낸다(규칙·숫자 → 기획, 화면·버튼·팝업·이펙트 → UI, 그림 → 이미지).
