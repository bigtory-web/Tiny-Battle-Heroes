# 기획 바꾸기 (규칙·숫자)

"1. 기획" 세션의 기본 절차다. 화면은 `handoff`, 되돌린 기획은 `decision-log`, 챕터는 `new-chapter`, 업그레이드는 `upgrade-node` 스킬을 같이 쓴다.

## 순서

1. **기록 먼저:** `기획결정기록.md`에서 비슷한 것을 찾는다. 예전에 해 봤다가 되돌렸거나 안 하기로 한 것이면, 만들기 전에 그때 무엇을 했고 왜 안 맞았는지 사용자에게 먼저 말한다.
2. **애매하면 묻기:** 숫자·구조(묶기·합치기·몇 개)는 사용자가 말한 것만 쓴다. 정해지지 않은 숫자가 꼭 필요하면 "임시"로 넣고 주석과 보고에 적는다. 방법이 안 정해진 요청이면 "이렇게 하려고 해요"를 한 줄로 먼저 말한다. 여러 질문은 한 번에 묻는다.
3. **고치기:** `data.js`(숫자·설정), `engine.js`(규칙·봇). `index.html`은 UI 몫이라 고치지 않는다(`handoff`).
   - 주석에 날짜와 사용자 말 원문을 남긴다. 예: `/* 2026-11-27 3장은 +1 더 (사용자: "3은 1더 올려") */`
   - 엔진이 새 값을 화면에 줘야 하면 함수로 내보낸다(`api`에 추가). 화면이 계산을 따로 하지 않게 한다.
   - 봇(`campaign`)도 같은 규칙으로 돌게 고친다.
4. **시험:** `node 영구강화_시험.js`에 시험을 더하고 전부 통과시킨다. 봇은 오류 없이 끝까지 도는지만 본다(승률은 사용자가 말하기 전엔 재지 않는다).
5. **숫자를 바꿨으면** 바뀌기 전·후를 표로 보여 준다.
6. **기록:** `개발일지/<오늘>/기획.md` 맨 아래에 항목(형식은 `개발일지/README.md`). 같은 작업의 작은 덧붙임은 "- 추가:" 한 줄.
7. **커밋·push:** 묻지 않고 한다. 내 파일만 `git add`. 메시지 끝에 Co-Authored-By 줄. 배포 얘기는 사용자에게 꺼내지 않는다.
8. **넘기기:** 화면·그림이 따라 바뀌어야 하면 `handoff`.
9. **보고:** 한 것, 기획이 정한 임시 값, 확인 못 한 것(화면은 안 봤음 등), 남은 질문.

## 안전하게 고치기 (실수했던 것)

- 여러 줄 스크립트는 bash heredoc 대신 **Write 도구로 스크래치 파일**을 만들어 `node`로 돌린다. heredoc은 백슬래시가 반으로 줄어 바꾸기가 빗나간 적이 있다.
- 글자 바꾸기는 `indexOf`로 **정확히 한 곳**인지 확인하고 바꾼다(`s.match(문자열)`은 정규식이 돼서 틀린다). 없거나 두 곳이면 멈춘다.
- 한 줄짜리 코드 뒤에 `//` 주석을 달면 뒤 코드가 주석이 될 수 있다. `/* */`를 쓴다.
- 고친 뒤 `node -e "require('./data.js');require('./engine.js')"`로 문법을 먼저 본다(data.js가 깨지면 로컬 화면이 멈춘다).
- 같은 방법으로 두 번 실패하면 멈추고 사용자에게 묻는다.

## 레벨로 오르는 것을 말할 때

`data.player` 표만 보지 말고 `grep -n "plv\|perLevel\|kingFrom\|heroLv" engine.js data.js`로 엔진 전체를 뒤져 빠짐없이 말한다(하트, 적 영웅 등급, 룰렛 등급, 상인 영웅 등급 등이 표 밖에 있다).
