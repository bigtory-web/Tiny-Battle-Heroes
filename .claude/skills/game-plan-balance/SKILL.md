# 밸런스 재기

재기만 한다. 직업 능력치·레벨 성장·등급·별·업그레이드 비용 같은 게임 숫자는 표를 보고 사용자가 정한다(정해지면 `game-plan-change`).

## 측정 단계 (2026-11-27 사용자: "테스트 정도는 3단계로 나누고")

| 단계 | 시드 | 한 번 잴 때 | 기준표 전체 | 쓸 때 |
|---|---|---|---|---|
| 1 | 10 | 20판 | 약 1분 | 방향만 볼 때. 칸마다 ±0.3레벨쯤 흔들림. 사용자가 단계를 안 말하면 1 |
| 2 | 100 | 200판 | 약 10분 | 숫자를 정하기 전 |
| 3 | 200 | 400판 | 약 20분 | 최종 확인 |

시드 하나 = 양쪽 자리를 바꿔 2판(자리 이점을 지움). 오래 걸리는 2·3단계는 백그라운드로 돌린다. 단계를 올릴지는 사용자에게 묻고, 판 수를 말할 때는 "시드 N개 × 양쪽 = 2N판"으로 말한다.

## 스크립트 (`밸런스/`)

| 파일 | 재는 것 | 돌리기 |
|---|---|---|
| `기준표.js` → `기준표.md` | A 직업 평균 능력치·레벨별 전투력(공식), B 능력치 가치(레벨 환산, 스킬 끔/켬), C 업그레이드 한 단계 가치, D 별(공식)·등급(영웅마다 대표 영웅과 바꿔 끼움) | `node 밸런스/기준표.js --stage=1` |
| `1레벨_DPS.js` → `.md` | 영웅마다 혼자 30초 허수아비 DPS(방어 0, 5판) | `node 밸런스/1레벨_DPS.js` |
| `대시보드_데이터.js` | 대시보드 CSV 3개: heroes, curve(챕터 3 × 난이도 3, 봇 20판, 업그레이드 없음), stat_value(최신 기준표 기록의 L 줄) | `node 밸런스/대시보드_데이터.js` |
| `능력치_가치.js` | 예전 방식(팀 전원 +10% 승률). 기준표 B로 대체됨, 참고용 | |

엔진: `createBattle(..., { statsOnly: true })` = 궁극기·패시브·초월 추가 스킬 끔(직업 효과는 남음). `E.powerCurve(data, { runs, meta })` = 봇 첫 판만 센 스테이지별 힘 곡선.

## 잣대

- 능력치 가치는 **레벨**로 환산한다: 표준 팀 거울 전에서 한쪽 영웅 하나에 능력치를 주고, 상대 같은 영웅의 체력·공격·방어(= 레벨)를 얼마나 올려야 비기는지 이분 탐색. 체력으로 환산하면 맞을 일이 적은 직업(마법사·암살자)에서 값이 흔들려서 바꿨다.
- 승패가 아니라 끝났을 때 남은 체력 차이로 잰다(같은 팀끼리는 승패가 거의 안 움직임).
- 승률은 참고로만 본다(`powerCurve`). 숫자를 바꿀 때마다 재지 않는다.
- 기준표가 "못 잼"으로 거르는 열: 검산 줄(체력·공격·방어 +25% = 1.0)이 0.5~1.5 밖이거나, 상대 영웅을 +50%·+150% 올려도 상대가 우세해지지 않을 때. 이런 열은 숫자를 지어내지 말고 못 잰 것으로 보고한다.

## 기록

- 스크립트는 `밸런스/기록.js`의 `save()`로 `밸런스/기록/<이름>_<날짜_시각>_<커밋>.json`에 쌓고, md 끝에 "지난번과 비교" 표를 붙인다. 지난번과 같으면 새로 안 남긴다.
- 커밋 뒤에 `+고침`이 붙으면 data.js·engine.js를 고친 채 잰 것.
- 새 스크립트도 같은 `save()`를 쓴다.

- 링크: https://claude.ai/artifact/Mi3CVjJr57HfRh2Gek1tgi (Data 유형, 사용자만 봄)
