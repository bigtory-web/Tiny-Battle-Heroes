# 작업 마무리 (모든 세션)

## 1. 확인

- 원래 있던 화면과 기능이 그대로인지 본다. 확인하지 못한 것(눈으로 못 봄, 휴대폰 화면 등)은 그렇다고 적는다.
- 요청받은 것만 바꿨는지 `git diff`로 본다. 다른 문제를 봤으면 고치지 않고 알린다.

## 2. 개발일지

`개발일지/<오늘>/<내 세션>.md` 맨 아래에 항목 하나. 세션 파일: `기획.md`, `UI.md`, `이미지.md`, `QA.md`, `페이지.md`, `홍보.md` (페이블 검수는 보고서가 일지). 파일이 없으면 만들고 맨 위 줄은 `# 2026-11-23 기획`처럼 쓴다. 다른 세션 파일은 고치지 않는다.

```
## [분야] 한 줄 제목 ⭐
- 버전: v345 (있으면)
- 한 것: 무엇을 바꿨나, 한두 줄
- 의도: 사용자가 요청하며 말한 이유. 원문을 따옴표로 그대로 옮긴다. 없으면 생략
- 숫자: 측정값 표나 전후 비교 (있으면)
- 결과: 확인한 것 / 확인 못 한 것
- 그림: img/....png (있으면)
```

- 분야: `기획`, `개발`, `QA`, `디자인` 중 하나.
- ⭐: 글감이 될 만한 것에만(되돌린 기획, 숫자로 확인한 테스트, 전후가 확 달라진 그림, 고민 끝에 방향을 바꾼 결정).
- 숫자 표는 마크다운 표. 밸런스·시스템 테스트는 `가설 → 해 본 것 → 숫자 → 결정 → 결과` 순서.

## 3. 커밋·push (묻지 않고)

- 내 파일만 `git add` 한다. 다른 세션이 고치는 중인(커밋 안 한) 파일은 건드리지도 stash하지도 않는다. `git pull --rebase`가 그 때문에 거절되면 커밋하고 바로 `git push` 한다.
- 백업 파일(.vN)은 만들지 않는다. 되돌리기는 git.
- 메시지 끝에 Co-Authored-By 줄.

## 4. 넘기기와 보고

- 내 역할이 아닌 일은 찾은 것과 함께 그 세션에 넘긴다. 형식은 `handoff` 스킬의 틀을 쓴다(머리말은 내 세션 이름).
- 사용자에게는 한 것, 확인한 것, 확인 못 한 것, 남은 질문을 쉬운 말로 짧게.
