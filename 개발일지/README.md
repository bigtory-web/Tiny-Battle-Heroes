# 개발일지 기록 형식

## 폴더 구조

- 날짜마다 폴더가 하나 있다. 예: `개발일지/2026-11-23/`
- 세션마다 자기 파일에만 쓴다. 다른 세션 파일은 고치지 않는다.
  - `기획.md`
  - `UI.md`
  - `이미지.md`
- 페이지 세션이 이 폴더를 읽어서 개발일지 글을 만든다.

## 하루 숫자 (`숫자.md`)

- 하루 작업이 끝나면 기획 세션이 `node 개발일지/숫자.js 날짜`를 돌린다. 날짜 폴더에 `숫자.md`가 생긴다.
- 들어가는 숫자: 화면 고친 횟수, 백업 파일 수, 새로 저장된 그림 수, 세션별 기록 항목 수(⭐ 수), 세션별 토큰(응답 수, 출력, 새 입력, 캐시 읽기).
- 토큰은 Claude Code 대화 기록에서 센 대략 값이다. 이미지 세션이 부르는 Codex 사용량은 빠져 있다.

## 언제 쓰나

- 작업 하나를 끝내고 보고할 때, 그날 자기 파일 맨 아래에 항목을 하나 더한다.
- 파일이 없으면 만든다. 맨 위 줄은 `# 2026-11-23 기획`처럼 쓴다.

## 항목 형식

- "의도"는 꼭 쓴다. 사용자는 요청할 때 이유를 같이 말한다. 그 말이 개발일지에서 가장 중요한 줄이다.

```
## [분야] 한 줄 제목 ⭐
- 버전: v345 (있으면)
- 한 것: 무엇을 바꿨나, 한두 줄
- 의도: 사용자가 요청하며 말한 이유. 원문을 따옴표로 그대로 옮긴다. 없으면 생략
- 숫자: 측정값 표나 전후 비교 (있으면)
- 결과: 확인한 것 / 확인 못 한 것
- 그림: img/....png (있으면)
```

- 분야는 넷 중 하나다: `기획`, `개발`, `QA`, `디자인`.
- ⭐는 개발일지 글감이 될 만한 항목에만 붙인다.
  - 되돌린 기획
  - 숫자로 확인한 테스트
  - 전후가 확 달라진 그림
  - 고민 끝에 방향을 바꾼 결정
- 숫자 표는 마크다운 표로 쓴다. 페이지가 그래프로 바꿀 수 있다.
- 밸런스·시스템 테스트는 `가설 → 해 본 것 → 숫자 → 결정 → 결과` 순서로 쓴다.
